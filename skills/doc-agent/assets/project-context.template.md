# Documentation context

Use this as a small section in existing project guidance. Keep only information that changes documentation decisions. Delete unused prompts rather than treating this template as a required form.

- **Readers and situations:** Roles, prior knowledge, language, supported environments, and constraints that matter.
- **Reader outcomes:** What readers should understand or accomplish; the observable sign of success.
- **Scope and versions:** Supported product versions, intended output formats, and explicit exclusions.
- **Canonical evidence:** Paths or links to current contracts, implementation, examples, tests, release information, and relevant user research. Identify material source conflicts.
- **Language:** Preferred product names and terms, terms to avoid, style guide, and useful examples of existing documentation. Preserve real API/UI identifiers.
- **Structure:** Existing content types, templates, navigation, and canonical destinations for reusable explanations.
- **Build and checks:** Existing package manager, lockfile, runtime requirements, documented build/preview/lint/test commands, and expected results. Commands require inspection before execution.
- **Maintenance:** Existing owner, release/versioning process, known gaps, and useful feedback channels.

Project-specific context should remain with the project. This file is a template; neither VS Code nor Doc Agent automatically treats its contents as product facts.
