# Design

## Context

See proposal.md for motivation. Bootstrap currently loads and validates current sources, collects desired files, and checks previous ownership before planning writes. The manifest already records file and routing-block SHA-256 hashes. Safe regular-file and ancestor checks already reject symlinks and special files.

## Goals / Non-Goals

**Goals:** Reuse safe reads and manifest validation while keeping check independent from package inventory, source rendering, update planning, and writes.

**Non-Goals:** Authenticating a maliciously rewritten manifest, detecting upgrades, changing recorded file permissions, or repairing drift.

## Decisions

- Add a dedicated integrity function that reads the manifest first and validates all paths before reading managed destinations. Reuse manifest validation with optional current inventory: absent inventory validates canonical skill names, so historical installations remain checkable after source removal.
- Validate required manifest structure, provenance field types, hashes, canonical ownership paths, and duplicate JSON keys. Preserve normal source-availability checks for bootstrap.
- Dispatch check before source inventory and suppress bytecode during the local helper import. Combining check with mutating or selection options is a CLI error.
- Compare file bytes and the exact bounded routing block to recorded hashes. Report drift across managed entries; ignore unowned entries and surrounding instructions. Reuse safe regular-file reads to refuse links instead of traversing them.
- Exercise the real subprocess CLI and compare snapshots including inodes, modes, and bytes for successful and failed checks; include a nested source to detect import-generated bytecode in the target.

## Risks / Trade-offs

- [Concurrent target changes] → Safe reads reject obvious unsafe paths; no atomic filesystem snapshot or concurrent adversarial-write guarantee is introduced.
- [Manifest edits can replace trusted hashes] → This is integrity against the project-owned record, not signature verification; Git remains the authority for reviewing record changes.
- [Older source removal] → Check never calls current inventory or renders the current routing block.

## Migration Plan

No manifest version change or migration is needed. Existing generated manifests are supported. Rollback removes the optional CLI mode; no project content is changed by checking.
